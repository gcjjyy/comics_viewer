# 만화 뷰어 설계

작성일: 2026-11-24

## 1. 무엇을 만드는가

ZIP으로 된 만화책을 맥·윈도우·리눅스 데스크톱에서 읽는 뷰어다. 만화는 내 컴퓨터 폴더에 있을 수도 있고, `~/.ssh/config`에 등록된 SSH 서버에 있을 수도 있다. 두 곳 모두 표지가 늘어선 책장으로 보여 준다. 일본 만화(오른쪽→왼쪽)와 한국 만화(왼쪽→오른쪽)의 넘김 방향이 다르므로, 방향에 맞춰 화살표 키와 화면 배치를 바꾼다.

원격 서버의 1GB 넘는 ZIP도 통째로 내려받지 않는다. 필요한 페이지만 가져와서 로컬 파일처럼 바로 열고 넘길 수 있어야 한다. 이 점이 사용 경험을 가장 크게 좌우한다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 로컬 폴더와 SFTP 폴더를 "서재"로 등록하고, 작품별 표지 책장으로 탐색한다.
- 두 쪽 펼침으로 읽는다. 넘김 방향은 일본식이 기본이고 한국식으로 바꿀 수 있다.
- 읽던 위치를 기억하고, 권 끝에서 다음 권으로 이어서 넘어간다.

**비목표 (만들지 않는다)**
- ZIP(CBZ) 외 포맷: RAR/CBR, PDF, 7z, 이미지 폴더
- 모바일·웹 버전
- 원격 서버에 파일 쓰기(진행 기록, 썸네일 등). 서버는 읽기만 한다.

**실패 조건 (동작해도 실패로 본다)**
- 원격 ZIP을 열 때 파일 전체를 받느라 오래 기다려야 함
- 한국어 파일 이름이 깨져 보임
- 일본 만화에서 페이지 짝이나 순서가 종이 책과 반대로 보임

## 3. 제약

- 스택: **Tauri 2** (Rust 코어 + 웹 프론트엔드). 사용자가 선택했다.
- 사용자는 Tauri를 처음 쓴다. 구조는 단순하게, 무거운 처리는 Rust에 둔다.
- 샘플 데이터: `/Users/gcjjyy/Downloads/QuickBASIC 4.5/만화` (ZIP 111개, 8.6GB). 확인된 특징은 다음과 같다.
  - ZIP 안 파일 이름이 UTF-8 플래그 없이 **CP949**로 저장돼 있다(샘플 전부).
  - ZIP 하나에 여러 권이 폴더로 들어 있는 경우가 많다(`슬램덩크 완전판.zip` 1.5GB, 24권 / `킹덤 526~635화.zip` 110화).
  - `Thumbs.db`, `.txt` 등 이미지가 아닌 파일이 섞여 있다.
  - 이미지는 `.jpg`가 대부분이고 `.png`도 있다.
- 사용자의 `~/.ssh/config`는 `Host`, `HostName`, `User`, `Port`, `IdentityFile`, `IdentitiesOnly`, `HostKeyAlgorithms +ssh-rsa`를 쓴다. `ssh-rsa` 호스트 키만 지원하는 오래된 서버가 있다.

## 4. 검토한 방식

| 방식 | 장점 | 단점 |
|---|---|---|
| **Tauri 2 (선택)** | 앱이 작고(수 MB) 메모리를 적게 쓴다. Rust로 ZIP 부분 읽기, SFTP, 이미지 처리를 빠르게 한다 | OS마다 웹 엔진이 달라 드물게 화면 차이가 날 수 있다. 뒷단이 Rust라 진입 장벽이 있다 |
| Electron | 모든 OS에서 화면이 같고 자료가 많다 | 앱이 150MB 이상이고 메모리를 많이 쓴다 |
| 네이티브 UI (Qt, egui 등) | 반응 속도가 가장 좋다 | 책장 그리드, 펼침 보기 등 UI를 직접 만들 양이 많다 |

사용자는 각 방식의 설명을 듣고 Tauri를 골랐다. 만화 뷰어의 무거운 일은 Rust가, UI는 웹이 빠르게 처리할 수 있기 때문이다.

## 5. 사용자가 정한 것

### 5.1 서재와 책장 (A안: 왼쪽 서재 목록 + 작품 표지)

- 왼쪽 사이드바에 서재 목록(로컬 폴더, SFTP 호스트+경로)과 "서재 추가", "최근 읽은 책"이 있다.
- 서재를 고르면 작품 표지 그리드가 나온다. 작품을 누르면 권별 표지 그리드로 들어간다.
- 표지 카드에는 표지, 제목, 권수, 진행 막대를 보여 준다. 진행 막대는 그 작품의 넘김 방향을 따른다(일본식은 오른쪽→왼쪽으로 찬다).
- 맨 위에 검색창이 있다(작품 이름 검색).

### 5.2 작품·권 묶는 규칙 (사용자 확인)

1. ZIP이 바로 들어 있는 폴더가 하나의 작품이다. 깊이는 상관없다. 작품 이름은 폴더 이름이다.
2. 서재 맨 위에 바로 놓인 ZIP은 그 자체로 작품이다.
3. 권 순서는 파일 이름의 숫자 크기로 정렬한다(1, 2, …, 10).
4. 작품 표지는 1권의 첫 이미지다.
5. ZIP 안에 이미지를 담은 폴더가 2개 이상이면, 그 ZIP은 작품 하나이고 안쪽 폴더 하나하나가 권이다. 폴더 이름도 숫자 크기로 정렬한다. 이 ZIP이 작품 폴더 안에 있으면, 안쪽 폴더를 그 작품의 권으로 펼쳐 넣는다.
6. 이미지가 아닌 파일은 무시한다. 이미지가 하나도 없는 ZIP은 책장에 표시하지 않는다.
7. 이미지 폴더(ZIP이 아닌 것)는 표시하지 않는다.

### 5.3 넘김 방향

- 전체 기본값은 **일본 만화(오른쪽→왼쪽)**: `←` 다음, `→` 이전.
- 한국 만화(왼쪽→오른쪽): `→` 다음, `←` 이전.
- 방향은 서재 → 폴더(작품) → 책 순으로 지정할 수 있고, 더 좁은 범위의 설정이 이긴다. 폴더에 "한국 만화"를 한 번 지정하면 그 안의 책은 모두 그 방향으로 열린다.
- 읽는 중에 단축키로 바꾸면 그 책에만 기억된다.
- 화면 좌우 클릭, 진행 막대, 펼침 순서가 모두 같은 방향 규칙을 따른다.

### 5.4 읽는 화면 (B안: 두 쪽 펼침)

- 기본은 두 쪽 펼침이다. 일본식은 오른쪽 페이지가 먼저다. 단축키로 한 쪽 보기로 바꿀 수 있다.
- 표지(첫 페이지)는 혼자 나오고, 이후 2·3, 4·5쪽으로 짝을 짓는다.
- 가로가 세로보다 긴 이미지(펼침 그림)는 혼자 크게 보여 준다. 짝짓기는 그 다음 페이지부터 다시 시작한다.
- 위 막대(책장으로, 제목·권, 방향/보기 전환)와 아래 막대(진행 막대, 페이지 번호)는 마우스를 움직일 때만 보이고 평소에는 숨는다.

### 5.5 SFTP

- `~/.ssh/config`의 호스트를 그대로 쓴다. 서재 추가 화면에서 호스트를 고르고 원격 경로를 탐색해 지정한다.
- `HostName`, `User`, `Port`, `IdentityFile`, `IdentitiesOnly`, `HostKeyAlgorithms`(`+ssh-rsa` 포함)를 반영한다.

## 6. 구현자 판단으로 정한 것 (사용자 확인 대상)

- **프론트엔드**: React + TypeScript + Vite.
- **짝 맞춤 밀기**: 스캔본은 페이지가 빠져 짝이 어긋나기 쉽다. 짝을 한 페이지 미는 단축키를 두고, 책마다 기억한다.
- **기타 넘기기**: `Space`는 방향과 관계없이 다음, `Shift+Space`는 이전. 마우스 휠도 넘기기로 쓴다.
- **다음 권 이어 보기**: 권의 마지막 페이지에서 한 번 더 넘기면 다음 권 첫 페이지로 간다. ZIP 안 폴더 권도 같다.
- **읽던 위치와 설정 저장**: 진행 위치, 방향, 짝 밀기, 서재 목록은 이 컴퓨터의 SQLite(앱 데이터 폴더)에 저장한다. 책 식별 키는 `서재 + 상대 경로 (+ ZIP 내부 폴더)`다.
- **썸네일 캐시**: 표지 썸네일은 앱 캐시 폴더에 저장한다. 원본 크기와 수정 시각이 바뀌면 다시 만든다.
- **책장 갱신**: 서재를 열면 캐시된 목록부터 바로 보여 주고, 폴더 변경 확인은 뒤에서 한다. 새 작품이나 사라진 작품만 반영해서 화면이 깜빡이지 않게 한다.
- **SFTP 인증 순서**: ssh-agent → `IdentityFile`(없으면 `~/.ssh/id_ed25519` 등 기본 키) → 키에 암호가 걸려 있으면 암호를 묻는다. 그래도 실패하면 비밀번호를 묻고, OS 보안 저장소(macOS 키체인, Windows 자격 증명 관리자)에 저장할지 선택하게 한다.
- **호스트 키 확인**: `~/.ssh/known_hosts`로 확인한다. 처음 보는 호스트는 지문을 보여 주고 사용자가 승인하면 접속한다. 키가 바뀐 호스트는 접속을 막고 그 이유를 보여 준다.
- **ZIP 파일 이름 인코딩**: UTF-8 플래그가 있으면 UTF-8로 읽고, 없으면 UTF-8로 검사해 맞으면 UTF-8, 아니면 CP949로 읽는다.
- **연결 끊김**: SFTP 연결이 끊기면 자동으로 다시 연결한다. 실패하면 읽는 화면에 "서버 연결이 끊겼습니다"와 다시 연결 버튼을 보여 준다.

## 7. 구조

### 7.1 Rust 코어

- **소스 계층**: 로컬 파일과 SFTP 파일을 같은 "읽기 + 위치 이동(Read + Seek)" 인터페이스로 감싼다. ZIP 처리 코드는 둘을 구분하지 않는다.
- **원격 블록 캐시**: SFTP 파일은 고정 크기 블록(예: 256KB) 단위로 읽고 메모리 LRU에 둔다. ZIP 목차(파일 끝)와 필요한 페이지 구간만 가져온다.
- **ZIP 인덱스**: 목차를 읽어 권 구분(5.2 규칙 5), 자연 정렬, 인코딩 변환, 이미지 필터를 거친 페이지 목록을 만든다. 열 때마다 다시 읽지 않도록 캐시한다.
- **이미지 전달**: Tauri 사용자 정의 URI 스킴(예: `comic://`)으로 페이지 바이트를 `<img>`에 바로 넘긴다. base64로 변환하지 않는다. JPEG/PNG는 원본 그대로 넘기고 디코딩은 웹뷰가 한다.
- **미리 읽기**: 현재 펼침 기준 앞으로 4쪽, 뒤로 2쪽을 미리 가져온다.
- **썸네일 생성**: 첫 이미지를 디코딩해 작은 크기로 줄여 캐시에 저장한다. 원격 서재는 동시 생성 개수를 제한한다.

### 7.2 프론트엔드

- 화면: 책장(서재 사이드바 + 작품 그리드 + 권 그리드), 읽는 화면, 서재 추가(로컬 폴더 선택 / SSH 호스트 선택 + 원격 경로 탐색), 설정(기본 방향).
- Rust 명령 호출(`invoke`)로 서재 목록, 작품·권 목록, 페이지 목록, 진행 저장을 주고받는다.

## 8. 라이브러리 후보 (구현 시 context7로 최신 문서와 버전을 확인)

- ZIP: `zip` 크레이트. 이름 원본 바이트를 읽어 직접 디코딩한다.
- 인코딩: `encoding_rs` (CP949 = EUC-KR 확장).
- SFTP: `russh` + `russh-sftp` 우선 검토. `ssh-rsa` 호스트 키, ssh-agent, 암호 걸린 OpenSSH 키 지원 여부를 확인한다. 부족하면 `ssh2`(libssh2)로 바꾼다.
- ssh config 파싱: `ssh2-config` 등. 빠진 지시어는 직접 처리한다.
- 저장: `rusqlite`. 비밀번호 보관: `keyring`.
- 썸네일: `image` 크레이트.

## 9. 테스트

- 샘플 폴더로 작품·권 묶기 결과를 검증한다(슬램덩크 24권, 킹덤 110화+7화, 이토준지 하위 작품들, 단권 ZIP).
- CP949 이름 디코딩을 단위 테스트한다.
- 펼침 짝짓기(표지 단독, 가로 이미지 단독, 짝 밀기, 방향별 좌우 배치)를 단위 테스트한다.
- 원격 블록 캐시: 큰 ZIP에서 한 페이지를 열 때 실제로 받은 바이트가 전체의 작은 일부인지 측정한다.
- SFTP 통합: 사용자의 `~/.ssh/config` 호스트 중 하나로 실제 접속해 확인한다(사용자 허락 후).
